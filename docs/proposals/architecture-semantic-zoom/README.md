# Architecture 图的语义缩放（LOD）设计

状态：设计已定稿（2026-10-23，经 14 轮真实页面原型迭代，PC 与手机、Quay OO 与 live voice 两个会话）。
实现任务：`architecture-semantic-zoom-layout`。
参考原型：`reference/prototype-v14.js`（浏览器内脚本，读取真实渲染出的 SVG 后在屏幕坐标里重画；仅作参考实现，不进产品）。
参考图：`reference/v14-montage-{pc,m}-{quay,voice}.png`，每张含 65 / 46 / 33 / 17 / 6 % 五个缩放档。

## 要解决的问题

缩小后，现行做法有三类毛病：实体被整层隐藏而包框保持满尺寸（大块空白）；包名与类名越缩越小到不可读；覆盖层标题互相重叠、与原标题重影。

## 原则

1. **基线是原布局乘缩放。** 缩放到约 90% 以上时完全还原，缩放过渡连续。
2. **每个可见元素有最小尺寸。** 包要在框内左上角留一条标签带（字号 + 6px 高，宽度放得下标签与 ★ 计数）；类框要容得下标题格加两个小格，宽度放得下类名（上限 130px，放不下折两行或中间省略）。文字固定在最小字号（PC 10px、手机 11px），放不下就省略，绝不缩小。
3. **满足最小尺寸只靠单调拉伸。** 对 x、y 各做一次分段线性映射，只在约束不满足处增大间距，其余保持缩放后的间距。左右上下顺序、对齐、包含关系、折线边的正交性因此全部保留。
4. **文字隐藏的类框可以压缩。** 空的类体压到最小，压缩量随缩放比从 0 渐变到 100%（约 90% → 50%）。类框从它的格子左上角起按紧凑高度绘制，格子仍参与布局；边的端点跟随。
5. **拉伸预算超过 1.8 倍就降一级，不硬撑。** 档位：A 类名与成员 → B 只留类框 → C 只留包。
6. **被 LOD 隐藏的信息要在上一级汇总，不能无声消失。** 包名后保留 `(N)`；C 档在包标签后加橙色 `★N`（该包内被会话直接提到的实体数）。
7. **UML 形态不退化。** 包标签是完整的小矩形标签页（含右侧封口）；类框始终保留「标题 / 属性 / 方法」两条横线，成员文字隐藏后也画；接口只有方法时一条。

## 七条规则（实现时逐条验收）

1. 每个元素按屏幕尺寸决定：成员 → 类名 → 仅外框 → 隐藏（外框宽 < 10px 或高 < 6px）。
2. 文字固定在最小字号；放不下就省略。
3. 类名放不下时依次：整行、按驼峰折两行、中间省略（非高亮 ≥ 9 个字符，被提到的 ≥ 6 个）。
4. 包名是框内左上角的文字加下划线、右侧封口的标签页，只显示最后一段加计数；包框顶边滚出视口时，标签贴到该框可见左上角，最多保留 2 个。
5. 边画在节点之下，按视口内可见边数降低不透明度（> 100：0.18，> 40：0.3，> 22：0.5，否则 0.85）。
6. 缩放以内容最密的窗口为锚点，不用整图包围盒中心。
7. 被提到的实体用橙色边加淡橙底；接口浅蓝底、枚举浅黄底。

## 算法要点

- 断点：所有可见元素在该轴上的边界坐标去重排序；约束形如「断点 a 到断点 b 至少 m 像素」。
- 前向一遍：`Q[k] = Q[k-1] + 缩放 × 原间距 × (可压缩 ? 1-α : 1)`，再对以 k 为终点的每条约束取 `max(Q[k], Q[a] + m)`。可压缩间距指：覆盖它的所有类框都处于「文字隐藏」状态。
- 约束：类框最小宽高；包的标签带（父顶边到最上子元素顶边 ≥ 标签高）、标签宽度（包宽 ≥ 标签宽 + 8）、子元素与包边至少 3px。
- 档位选择：A、B、C 依次试，取第一个 `max(Rx, Ry) ≤ 1.8` 的档（R = 解出的总尺寸 / 缩放后的原总尺寸）。
- 边：折线端点按同一映射变换；落在被缩短类框底边或侧边上的端点随之上移；箭头保持屏幕尺寸并随端点平移。

## 已知局限（实现时需处理）

- 档位切换没有滞回，边界附近缩放可能来回跳档，需加死区（沿用现有 8% 死区与 200ms 防抖的做法）。
- 手机 17% 的粘性包名偶尔盖住上方类名。
- 原型是对 SVG 的覆盖重画；产品里要重写几何，命中测试、拖拽、小地图、选择、置顶 / 排除徽标都要经这套映射。
- plantuml-js 0.4.0（2026-10-23 发布）已提供分格与几何：`uml-compartment-rule`（`data-rule="title|ops"`，接口只有 title 一条）、成员 `uml-attr` / `uml-op`、闭合的 `uml-package-tab`、`uml-node` 的 `data-x/y/w/h` 与 `data-title-h/attrs-h/ops-h`、`uml-package` 的 `data-x/y/w/h` 与 `data-tab-w/h`、聚合边 `uml-edge-bundle`（`data-bundle-size`）。实现直接读这些，不再用「成员文本含 `(`」推断；`reference/prototype-v14.js` 是在 0.3.1 的 SVG 上写的，仍含这类推断，仅作行为参照。
- 「单调映射 + 约束求解 + 降档」本身暂不进 plantuml-js `/ui`（plantuml-js 会话意见：先在应用侧落地验证，若成为通用需求再把纯函数原型整理给它）。
