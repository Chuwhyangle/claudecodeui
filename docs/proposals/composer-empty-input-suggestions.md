# 输入框空态建议项 Proposal

状态：Proposal / 已评审（人 yale 2026-10-23 确认外观、Tab 语义、采用方式、窄屏四项）
证据基础：本轮对本机近 7 天会话的量化分析（脚本见 `experiments/composer-input-suggestions/`）与可交互原型（`docs/proposals/assets/composer-empty-input-suggestions/prototype.html`）
落地任务：`gap-composer-empty-box-history-frequency-chips`（第一档）

---

## 摘要

输入框为空、且助手空闲时，把「你过去常发的短输入」以虚线 chip 的形式直接显示在 textarea 里（不新增一行），
用 Tab / 鼠标 / Enter 选择；一旦框里有任何字，chip 全部消失，清空后重现。

量化结论先行：**可用建议的上限只有约 15–20% 的回合**。一半以上的输入是全新内容，任何检索或模型都猜不到。
所以本提案分三档，只落地最便宜、可证伪的第一档（纯频次检索，不调模型）；LLM 生成档要等第一档的真实采纳率出来再决定。

---

## 背景与现状

均为本轮读码核实：

- **同会话历史已存在**：`src/modules/chat/hooks/useInputHistory.ts`。空框按 ↑ 翻本会话已发送的消息，存于 `localStorage['chat-input-history']`，
  按 scope（sessionId 或 `project:<id>`）分桶，每桶 ≤100 条、最多 100 个桶，只在**送达后**记录（`recordSentMessage`）。
- **按键分流顺序**（`useChatComposerState.ts` 的 `handleKeyDown`）：命令菜单 → 文件提及 → 历史（↑/↓）→ Tab 切权限模式（`cyclePermissionMode`）→ Enter 发送。
- **Tab 现为切权限模式**，无条件（只要没开 `/`、`@` 菜单）。
- **textarea 有一层透明镜像**（`ChatComposer.tsx` 中 `inputHighlightRef`，`pointer-events-none`），只做高亮，接不了鼠标事件，所以 chip 不能画在这一层。
- **全局 Escape = 中止会话**（`ChatInterface.tsx` 的 `handleGlobalEscape`，document capture 阶段）：仅在 `canAbortSession` 时注册；焦点在 composer textarea 且页面上没有 `role=dialog|menu|listbox` 时才中止。
- **客户端消息里没有 `stop_reason`**：`NormalizedMessage` 无截断标记，前端无法判断「助手回复被截断」。
- **发送失败时草稿仍留在框里**：`commitSentComposerState` 只在送达后清框，失败路径保留草稿，所以失败后框不是空的。

## 数据依据

范围：本机 `~/.claude/projects` 近 7 天，6 个项目、87 个会话。剔除自动化提示词（quay worker/gate 模板、语音 relay、任务通知）后，
**1128 条用户亲手输入**。

| 指标 | 读数 |
|---|---|
| 长度 p25 / p50 / p75 / p90 | 14 / 33 / 80 / 188 字；≤15 字占约 27% |
| 与前序内容的关系 | 全新内容 54%；指代回指（上面/这个/该）15%；其他短句 14%；检查进展类 9%；同意/继续类 7%；反驳 1% |
| 精确重复过去某条输入 | 14% |
| 上一轮助手以提问/建议收尾时，用户用肯定词回复 | 43/574 = 7.5% |
| 会话首条（无前序） | 6.7% |
| 高频短语 | 「检查进展」47（4.2%）、「继续」23（2%）、「同意」14 |

**纯检索基线**（按时间顺序回放，每条输入只能用它之前的历史；hit@3 = 3 个 chip 中有一个与实际输入完全相同）：

| 策略 | 全部 | ≤30 字 | ≤15 字 |
|---|---|---|---|
| 全局高频 top3 | 7.1% | 15.0% | 25.2% |
| 项目内高频 top3 | 5.7% | 12.1% | 20.2% |
| 按「助手上一轮结尾相似度」检索 | 7.2% | 15.0% | 24.8% |

两点要紧：**全局高频不输项目内高频**（所以第一档不必按项目分桶，也就不需要 localStorage 里本不存在的项目映射）；
**上下文相似度只多出 1–3 个点**，不值得第一档引入。

**LLM 生成（haiku 5.5，38 个真实场景）**：判官口径 hit@3 = 26%（10/38），人工复核剔除 3 个误判后约 16–18%；hit@1 = 13%。
命中的几乎都是「同意 / 继续 / 检查进展 / 带具体名词的同意」。每次调用实测均价约 $0.0010（含约 10k token 的 CLI harness 固定开销，直连 API 会低于此），
延迟 p50 1.6s、最大 2.8s；按每天 150–271 个回合估算约 $4.5–8/月（上限口径）。n=38，误差约 ±12 个点，只能当数量级。

局限：单用户、7 天、且是重度自动化工作流下的数据；「提问」是启发式识别；回放用精确匹配（偏保守）。

## 交互规格（已确认）

1. **外观**：虚线 chip + 右侧操作提示（`Tab 选择 · ↵ 采用 · Esc 隐藏`）。叠在空 textarea 里，**不新增行**：
   有 chip 时输入框主体高 44px，无 chip 时 40px（原型实测），整个 composer 只差 4px。chip 可带来源小标签（常用 / 历史），是否保留见开放问题。
2. **Tab 语义**：Tab 先在 chip 间循环；走过最后一个后回到原有含义（切权限模式）。Shift+Tab 反向，走过第一个同样回落。chip 不可见时 Tab 完全保持原样。
3. **采用方式**：点击或 Enter 一律**「填入再发送」**——文本进入输入框、光标在末尾、chip 随之消失，用户可编辑后再按 Enter 发送。不做「直接发送」。
4. **窄屏**：chip 保持单行，横向滚动；不显示操作提示。

可见条件（全部满足才显示）：输入为空；助手空闲（非 `isLoading`）；命令菜单与文件菜单都没开；没有排队草稿、没有附件；输入未被占用（`isOccupied`）；有至少 1 个建议；本轮未被 Esc 隐藏。

焦点始终留在 textarea（chip 的 `mousedown` 不抢焦点，选择走 `aria-activedescendant`）。直接输入任何字符即消失。
Esc 隐藏本轮建议，直到下一个回合边界（助手一轮结束，或切换会话）；Esc 不得触发中止会话。

## 方案分档

### 第一档（本提案落地）：全局频次检索，不调模型

- **数据源**：`chat-input-history` 跨全部 scope 聚合（新增 `readAllInputHistory()`）。零后端、零网络。
- **候选规则**：单行、≤60 字、不以 `/` 开头；大小写与尾部标点归一后计数；出现 ≥2 次才入选；按频次降序、同频按最近使用；取前 3；无历史则不显示（不硬编码任何种子短语）。
- **采纳读数**：本地计数器（展示 / 采纳 / Esc 隐藏 / 被输入打断），不联网，作为第三档的决策依据。

**从原设想里拿掉的两条「场景规则」及原因**：

- 「回复被截断 → 继续」：客户端没有截断信号；且 7 天数据里上一条 assistant 记录的 `stop_reason` 为 end_turn 969、stop_sequence 66、tool_use 12、缺失 3，**没有一条 max_tokens 截断**，非正常结束合计约 1.4%（15/1050）。「继续」由频次自然带出即可。
- 「发送失败 → 重试」：失败时草稿仍留在框里，框不为空，chip 根本不会出现；重试靠现有的 `sendFailed` 路径。

### 第二档（候选，需单独立项）

- 上下文相似度重排（+1–3 个点）。
- 服务端聚合接口：跨设备，并含引入本功能之前的历史（localStorage 只从 `chat-input-history` 上线后开始累积）。
- 向客户端透传 `stop_reason`，使「继续」成为有信号的场景规则。

### 第三档（候选，opt-in）：LLM 生成

前置条件：第一档上线后，本地采纳率读数显示值得继续投入。方案要点：回合结束时预取（延迟被阅读时间吃掉），haiku，只发上一轮回复尾部 + 本会话最近 3 条输入 + 你的高频短句，要求 3 个候选；
默认关、设置项开启、按 `(sessionId, lastTurnId)` 缓存。真实价值主要是在「同意/继续/检查进展」里按上下文挑一句并补上名词，内容型输入基本猜不到。

## 风险与开放问题

1. **隐私**：chip 被动显示过往输入原文。与现有 ↑ 历史同属本浏览器本地信任域，但屏幕共享时是被动暴露。是否需要设置项关闭——**第一档不含设置项，待确认**。
2. **误触发送**：已由「填入再发送」规避。
3. **Tab 多一步**：空框且有 chip 时，切权限模式要先走完 chip；已确认接受。
4. **「Escape 误中止」**：chip 只在助手空闲时出现，此时全局 Escape 处理器本就未注册；chip 容器用 `role=listbox` 时该处理器还会因「存在 listbox」而放弃接管，两条保护同向。落地时要用测试钉住，并确认没有别的「是否有浮层打开」探测器把 chip 容器误当成浮层。
5. **命中率预期**：第一档整体约 7%、≤15 字约 25%。这不是 AC，是上线后用采纳读数核对的预期；低于预期不构成回退理由，只影响第三档是否值得做。
6. **来源标签（常用/历史）**：原型默认显示，第一档只有一个来源，标签没有信息量——**第一档默认不显示**。
