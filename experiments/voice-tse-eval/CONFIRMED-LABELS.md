## 3. 旁人先说话：单吸引子会锁错人，双钥匙才安全

把每条非目标切成 2 秒 turn，模拟“旁人先形成会话吸引子，然后目标说话”：

- 13 条可切分的非目标中，**7 条**（5 LibriSpeech + 1 EOT + 1 TTS）在开头 2–4 秒 score < 0.35 且内部一致性 ≥ 0.60，**会形成一个自洽的会话吸引子**。
- 如果只用这个会话吸引子判定，**15/15 条目标 turn 全部被拒绝**（score < 0.30）。
- 如果同时接受 **core**（5 条注册的质心），**15/15 条目标 turn 全部被接受**（score ≥ 0.30）。

结论：**会话吸引子只能用于“跟踪”，不能单独用于“授权/送 TSE”。**

建议的 **dual-key** 规则：

```
accept_tracking = max(score_session, score_core) >= TRACK
authorize_tse   = 该 cluster 已由 core 确认（cluster 的得分 >= MATCH_FAST）
```

- 旁人先说话 → 会话吸引子 = 旁人；但 core 不接受它，所以 **不授权 TSE**；
- 目标随后说话 → 目标 turn 仍然被 core 接受；系统把会话吸引子 re-anchor 到目标 cluster；
- 如果目标换了设备、core 暂时不接受 → 新 cluster 只能是 **provisional**，先跟踪、不 TSE；等它跨会话复现或被用户确认后再授权。

## 4. 选择器实验：VoxLock live() vs core 选择

序列：4 秒旁人（`en__713`，开头就有语音）→ 4 秒目标（`test-06`）→ 8 秒 0 dB 重叠。

| 方式 | SI-SDRi(target) | cos_target | cos_bystander | 结果 |
|---|---:|---:|---:|---|
| 未处理混合 | +0.31 | 0.58 | 0.06 | — |
| `VoxLock.live()` | **−2.31** | 0.366 | **0.733** | **锁到旁人** |
| **core 选择器** | **+15.54** | 0.656 | **0.043** | **锁到目标** |
| 取旁人前 3 秒做样本 | +1.83 | 0.599 | 0.071 | 不稳定 |

窗口分数（2 秒窗，0.5 秒步长）：

- 旁人段：0.02–0.17（低于 0.35）；
- 目标段：0.50–0.62（高于 0.35）；
- 选择器在 **4.0 秒**（目标开始处）选中 3 秒窗口。

对照：目标先说话的序列，`live()` 与 core 选择器都正常工作（SI-SDRi +15.5 左右）。

扩展到 2 个目标 × 2 个旁人（4 个 bystander-first 序列，`VoxLock(threads=4)`）：

| 序列 / 方法 | SI-SDRi(target) 中位数 | SI-SDRi(bystander) 中位数 |
|---|---:|---:|
| bystander_first / `live()` | **−2.26** | **+14.88** |
| bystander_first / core 选择器 | **+15.56** | **−28.38** |
| target_first / `live()` | +15.53 | −41.07 |
| target_first / core 选择器 | +15.55 | −41.85 |

逐条看，bystander-first 下 `live()` 在 3/4 个序列锁到旁人（SI_T −30.25 / −20.60 / −2.26），只有 1 个序列因为旁人开头能量低而侥幸锁到目标；core 选择器 4/4 全部锁到目标（+11.68 ~ +16.73）。

**结论：`live()` 的响度/先到先得策略在旁人先说话时会把 TSE 锁到旁人；用确认过的 core 选段可以把中位 SI-SDRi 从 −2.26 提到 +15.56。**

> 工程注意：`VoxLock()` 默认 `threads=0`，在 64 核机器上实测占用 ~58 核（5795% CPU）。并发会话应显式设 `threads=4`（或更小），否则 CPU 会被单连接吃满。

## 5. 真实会话上的 VoxLock：不作为质量结论

在真实 Live Voice turn（同一用户，已确认 03 的 6 条来自这些会话）上做 0 dB 合成干扰：

- 34 个 (turn × method) 读数；
- `session`（同会话首 turn 做样本）中位数 **−1.17 dB**，仅 7/34 为正；
- `cross`（跨天注册）中位数 **−3.32 dB**，6/34 为正；
- `auto` 中位数 **−4.73 dB**，4/30 为正；
- 极端值 −152 dB，说明样本/输出可能已经是旁人或者接近静音。

原因不是“TSE 一定无效”，而是这份真实数据**不适合做 TSE 质量评估**：

- turn 内可能含助手 TTS 回声、旁人、噪声，没有干净参考；
- 首 turn 常短于 3 秒，pad 后的样本不稳定；
- 部分会话内部一致性只有 0.26–0.49，像多人/回声会话。

**TSE 质量仍以 02/03 的合成混合矩阵为准**（session-local VoxLock 中位数 +10 dB；跨天失败）；真实会话用于**门控/跟踪覆盖率**，不用于 SI-SDR。

## 6. 对机制设计的更新

1. **门控/吸引子嵌入换成 CAM++ zh_en advanced**（跨天 EER 2.6%，比 CAM++ zh-cn 的 7.8% 好一个量级）。
2. **dual-key**：`accept_tracking = session_attr OR core`；`authorize_tse = cluster 已由 core 确认`。
3. **旁人先说话**：会话吸引子会形成，但不授权 TSE；core 继续接受目标 turn，并在目标出现后 re-anchor。
4. **阈值**：`MATCH_FAST=0.35`、`TRACK=0.30–0.35`、`PROMOTE=0.40`，以 462 条负样本的 0 误接受为当前工作点；中文负样本到位后重标。
5. **新设备/新 cluster**：provisional，只跟踪、不 TSE；跨会话复现或被用户确认后才授权。这样不会为了“适应漂移”而把旁人学成用户。
6. **VoxLock**：只用 core 确认过的会话内 3–4 秒原始音频做样本；不要用 `live()` 的先到先得；会话结束丢弃样本。
