## 背景

2026-10-19 讨论语音输出机制，结论：语音输出是「信心层」不是「信息层」。信息传递靠屏幕（完整、可回看、不可错）；语音输出的唯一职责是让用户——尤其不看着 PC/手机时——持续获得「系统在听、听懂了一些、可以继续说」的信心。北极星 KPI = 给出确认后用户是否继续往下说，而非「说了多少/多准」。

贯穿性质：异步（触发/生成/播报三条独立时间线，relay 保持「笔」，播报走旁路 narrator）；双工可打断（打断 = 对话推进不是异常，被打断的播报丢弃不补）；短信号换等待（一个「嗯」换数秒 silence window，非等长填充）；前重后轻（结论在前，后半段随时可被打断丢掉）。

已在本会话验证（证据在 experiments/ 与工作区）：
- 占位确认 announce 模式：`closingTurn` 加 `announce` 枚举，离线测试 20/20 绿 + typecheck 过；真机 replay（P1 窗口，¥0.02）转交后模型说「好的，我来查找 quay 最活跃的会话」（9 字、非 OK、非复述），打断后说「已为您终止当前操作」（待调优）。
- 结束总结生成：`experiments/voice-realtime-announce-summary/summarize.mts` 用本项目真实会话输出（3057 字）喂 qwen3.8-omni-flash，产出 32–41 字小结（无 Markdown、verbatimTail≈0，voice 变体自发带「等你拍板」）。

## 范围

语音输出四个时机 + 横切底座：
1. 占位确认（转交后说「好的，我来做 X」）—— AC-403。
2. 结束总结（run 结束 → narrator 生成 ≤40 字小结，文本层先闭环）—— AC-404。
3. TTS 接入（cosyvoice-v3.5-flash 合成 + 浏览器播放）—— AC-405。
4. 双工打断 + 可清空队列（播报中用户开口即停、队列即清）—— AC-406。
5. backchannel（停顿「不确定态」给「嗯」，换更长 silence window）—— AC-407。

横切底座 E0：端到端验证/开发平台——MCP 浏览器 + HTTP + DashScope 各服务，无人值守把现有 wav 语料驱动过「离体能力探针 → 服务器回归 gate → 浏览器端到端」三层，分别服务开发/测试/验证。是 AC-404 之后一切真机验证的前置。
配套 C1：回声消除（AEC）——I3（开始出声）后、I5（说话频率陡增）前先验浏览器 `echoCancellation` 遮不遮得住外放；遮不住才上真 AEC（远端参考信号）。

## 非目标

- 不做「进展 update」（执行中断续进展）：等 AC-403 到 AC-406 跑通后，看「静默焦虑」是否真实存在再决定。
- 不让 relay 模型兼职「总结员」：总结由旁路文本模型生成，relay 保持「笔」。
- 不引入新 UI。
- 不发布、不重启 :3001（上线需人工 build/restart）。
